# Try-on model pipeline

Builds `assets/models/walker/walker-{m,f}.glb` + `walker.json` and the studio placeholder shoes.
Everything is generated by script, so it can be rebuilt and tuned rather than hand-patched.

## What it makes

| Part | How |
| --- | --- |
| Body | MakeHuman base mesh + macro targets (CC0, from MPFB2), with real morph targets `height_lo/hi`, `weight_lo/hi`, `muscle_hi`. The skin textures, hair, brows, lashes and eyes are carried over from the previous model and refitted to the new head. |
| Skeleton | MPFB "default" rig (163 bones), joints recomputed for every morph, so the viewer can move the joints with the body (`morph_joints` in `walker.json`). |
| Idle | Weight on one leg, relaxed arms and hands, natural foot spacing and toe-out, two breaths and a slow sway in 9 s. |
| Walk | Analytic leg IK. Heel strike → foot flat → heel off → toe off, with the stance foot locked to a floor moving at `walk.speed`. Pelvic bob, list and rotation, counter-rotating thorax, arm swing, toes flat during heel rise. |
| Garments | Hoodie (hood, drawcords, kangaroo pocket, rib hem and cuffs, chest print), joggers (rib cuffs, waistband), shirt (collar, placket, buttons, cuffs), trousers (turned hems, waistband, belt). Each is separate geometry built around the standing body: convex cross-sections plus ease, fabric hanging from the widest point, voxel-fused, with folds where real cloth folds. Skin weights come only from the right body region, the bind pose comes from exact inverse skinning, and the body's morphs are transferred. |
| Body variants | `Body_casual` / `Body_formal`: skin fully hidden under each outfit is removed, so it can't poke through. |
| Socks | From the foot and ankle of the body. |
| AO | Baked per outfit in Cycles, stored as a vertex colour. |
| Studio shoes | `build_shoes.py`: a plain white sneaker and a plain black derby. They're **not YOLO products** and the site says so. |

## Rebuild

Needs Python 3.13, `pip install bpy` (Blender as a module), numpy, Node + `@gltf-transform/cli`, and the MPFB2 data:

```bash
git clone --depth 1 https://github.com/makehumancommunity/mpfb2 /tmp/mpfb2
export MPFB_DATA=/tmp/mpfb2/src/mpfb/data
# the previous GLBs supply the skin/eye/hair textures and head proxies; decode them once
npx gltf-transform cp assets/models/walker/walker-m.glb /tmp/walker-m-src.glb
python3 tools/tryon/build_walker.py m --src /tmp/walker-m-src.glb --out /tmp/walker-m.glb --meta /tmp/walker-m.json
npx gltf-transform meshopt /tmp/walker-m.glb assets/models/walker/walker-m.glb
# same for f; then merge the two meta files into assets/models/walker/walker.json ({"M": ..., "F": ...})
python3 tools/tryon/build_shoes.py /tmp/shoes && npx gltf-transform meshopt /tmp/shoes/studio-sneaker.glb assets/models/shoes/studio-sneaker.glb
```

Previews: `--preview out.png` renders Cycles views; `PREVIEW_OUTFIT=formal`, `PREVIEW_EXTRA='[...]'` add views.
The site viewer has a QA hook when opened as `/try-on?qa`: `window.__walkerTest({body, outfit, motion, time, h, kg, eu, view})`.

pip's `bpy` wheel doesn't ship the Draco library, so decode Draco GLBs with gltf-transform first. Output is meshopt-compressed, and three.js decodes it with `MeshoptDecoder`.

## Adding a real shoe (a 3D scan/model of an actual product)

1. Export a **right** shoe as GLB: real-world metres, toe towards +z, heel at z = 0, sole bottom at y = 0, centred on x. PBR materials. Aim for under 1 MB after `gltf-transform meshopt`.
2. Add it to `assets/models/shoes/manifest.json` under `products`, keyed by the product's slug in `lib/catalog.js`:

   ```json
   "axel-penny": { "file": "/assets/models/shoes/axel-penny.glb", "size_eu": 42, "length_mm": 292,
                   "sole_mm": 18, "collar_mm": 55, "side": "right",
                   "colours": { "patent-black": "/assets/models/shoes/axel-penny-patent-black.glb" } }
   ```

   `size_eu` is the size the scan represents (the viewer scales it to the size the shopper picks). `sole_mm` is the insole height under the heel. `collar_mm` is the lowest point of the topline (the foot is hidden below it).
3. The product then appears selectable in the try-on picker, with no "Photo only" badge. Products without an entry are never drawn from a guess.
